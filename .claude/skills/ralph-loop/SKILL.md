# /ralph-loop

NEXTSTEP "나만의 Claude OS 만들기" 3주차 PRACTICE(`3주차.pdf` p27 "랄프 루프 직접 만들기")의 산출물.

> **랄프 루프(p4·p8)**: `while :; do cat PROMPT.md | (에이전트); done` — 고정된 프롬프트를 **목표 달성까지 무식하게 반복**한다.
> **핵심 통찰(p10)**: 진행 상황을 LLM 기억이 아니라 **파일·git에 저장**한다. 컨텍스트가 오염되면 세션을 버리고, 새 에이전트가 파일에 쌓인 결과를 보고 이어간다.
> **이름의 유래(p11)**: "똑똑한 한 방"이 아니라 **"단순 무식한 반복"이 이긴다**.

이 스킬은 그 루프를 우리 OS 안에서 **서브 에이전트 기반(p17 권장)** 으로 구현한다. 메인(나)은 루프를 도는 *오케스트레이터*이고, 실제 작업 1턴은 매번 새 서브 에이전트(독립 컨텍스트)가 수행한다.

## 0) 이 스킬이 담은 4가지 엔지니어링 (p15)

| # | 엔지니어링 | 이 스킬에서의 구현 | PDF |
|---|-----------|-------------------|-----|
| 1 | **독립 컨텍스트 활용** | 매 이터레이션을 새 서브 에이전트로 spawn → 컨텍스트 오염 리셋 | p16·17 |
| 2 | **세션·이터레이션 간 컨텍스트 공유** | 배운 것을 `lessons.md`에 append → 다음 턴 프롬프트에 재주입 | p19·20 |
| 3 | **백그라운드 & 병렬 서브 에이전트** | (옵션) 같은 목표를 N개 에이전트에 병렬로 주고 best 채택 | p21 |
| 4 | **정량적 목표 지표** | 정량 / 체크리스트 / 루브릭(LLM as a Judge) 으로 종료 판정 | p22~25 |

## 1) 인자 (파라미터)

```
/ralph-loop goal="<달성할 목표>" \
            verify="<증명 명령 또는 판정 방법>" \
            [metric=quant|checklist|rubric] \
            [max-turns=20] \
            [workdir=.] \
            [parallel=1]
```

| 인자 | 필수 | 의미 | 예시 |
|---|---|---|---|
| `goal` | ✅ | 달성할 목표(고정 PROMPT의 핵심) | `"E2E 전체 수행 시간을 5분 이하로 줄여라"` |
| `verify` | ✅ | **증명 방법** — 주장이 아닌 증거로 종료 판정 | `"npm run e2e가 exit 0이고 총 시간 < 300s"` |
| `metric` | ⬜ | 지표 유형 (기본 `quant`) | `quant` / `checklist` / `rubric` |
| `max-turns` | ⬜ | 턴 상한 (안전장치, 기본 20) | `15` |
| `workdir` | ⬜ | 작업 디렉토리 (기본 현재) | `./apps/web` |
| `parallel` | ⬜ | 1턴에 띄울 동시 에이전트 수 (기본 1) | `3` |

> 인자가 비면 되묻지 말고 **합리적 기본값**으로 채우되, `goal`·`verify` 둘 중 하나라도 없으면 **반드시 먼저 물어본다**. (종료 조건이 없으면 루프가 안 끝난다 — p18)

## 2) 시작 전 준비 — "미리 정의돼야 하는 것" 세팅

루프를 돌기 전에 `workdir`에 아래 두 파일을 만든다(이미 있으면 재사용).

1. **`.ralph/PROMPT.md`** — 한 번 정의·고정되는 작업 지시 (p9). 아래 템플릿으로 생성:

   ```markdown
   # 목표
   {goal}

   # 종료 조건 (이게 충족되면 끝)
   - 증명: {verify}
   - 제약: 기존 테스트를 깨지 마라 / 무관한 파일을 건드리지 마라
   - 상한: 최대 {max-turns}턴 (넘으면 중단하고 사람에게 보고)

   # 작업 규칙
   - 진행/교훈은 반드시 .ralph/lessons.md 에 append 한다 (네 기억을 믿지 마라).
   - 한 턴에 "한 걸음"만 전진한다. 끝났다고 주장하지 말고 증명({verify})으로 보여라.
   ```

2. **`.ralph/lessons.md`** — 누적 컨텍스트(이력 로그, p19). 없으면 빈 파일로 생성:

   ```markdown
   # Lessons (이터레이션 누적 기록)
   <!-- 매 턴 끝에 "무엇을 했고 / 무엇을 배웠고 / 다음 턴이 알아야 할 것" 1~3줄 append -->
   ```

> `.ralph/`는 LLM 기억이 아니라 **파일에 상태를 두는** 곳이다(p10). git에 커밋하면 세션이 죽어도 살아남는다.

## 3) 동작 — 루프 알고리즘 (오케스트레이터로서의 나)

```
turn = 0
while turn < max-turns:
    turn += 1

    # (A) 이터레이션 입력 조립 = 독립 컨텍스트 + PROMPT + 누적 컨텍스트   ← p9 흐름도
    prompt = read(.ralph/PROMPT.md) + "\n\n# 지금까지의 교훈\n" + read(.ralph/lessons.md)

    # (B) 실행을 메인 밖으로 분리 → 독립 컨텍스트 (p16·17)
    #     parallel=1 : 서브 에이전트 1개 spawn
    #     parallel>1 : 같은 prompt로 N개 동시 spawn 후, 가장 좋은 결과 채택 (p21)
    result = spawn_subagent(prompt, workdir)        # Agent 도구 사용

    # (C) 서브 에이전트가 배운 것을 .ralph/lessons.md 에 append 했는지 확인 (p19)
    #     (안 했으면 메인이 result 요약을 대신 append)

    # (D) 종료 판정 — metric 유형에 따라 (p22)
    if judge(verify, metric) == PASS:
        announce("✅ {turn}턴 만에 목표 달성"); commit_if_asked(); break
    else:
        # 미충족 → 이유를 lessons.md에 남기고 다음 턴으로 (p18 "미충족 시 이유 주고 재시작")
        continue

else:
    announce("⛔ {max-turns}턴 상한 도달 — 현재까지 진행과 막힌 지점 보고")
```

### (B) 독립 컨텍스트 실행 — 두 방식 (p17)

- **서브 에이전트 (기본·권장)**: `Agent` 도구로 매 턴 새 에이전트를 띄운다. 메인은 결과값만 받는다. → 컨텍스트가 이터레이션마다 깨끗하게 리셋된다.
- **Headless (며칠 돌릴 때)**: 같은 폴더의 `ralph.sh`를 쓴다. `claude -p`를 bash 무한 루프로 돈다. → 사람이 자리를 비워도 계속 돈다. (단, p17 참고: Headless는 과금·민감 이슈가 있어 평소엔 서브 에이전트 권장)

### (D) 종료 판정 — metric 유형별 (p22~25)

| metric | 판정 방법 | 쓰는 때 |
|---|---|---|
| `quant` (기본) | `verify` 명령을 실행해 **exit code·수치**로 판정 (테스트 PASS, 시간 < N초, 정확도 ≥ 90%) | 기계로 측정 가능할 때 |
| `checklist` | 체크 항목을 모두/ n개 이상 통과했는지 | 항목이 명확할 때 |
| `rubric` | **LLM as a Judge** — 별도 평가자 서브 에이전트가 루브릭으로 채점. 신뢰도 위해 **pass@N**(여러 번 채점)·**게이트 채점**(가장 낮은 차원이 결정, 한 차원이라도 기준 미달이면 미통과) | 정성 품질(UX·기획 등)을 점수화할 때 |

> 루브릭은 **재현성**이 강점이지만(p23), 긴 답·앞선 답을 선호하는 **편향**이 있으니 다관점 + 여러 번 채점으로 보정한다.

## 4) 출력 형식

매 턴마다 한 줄로 진척을 보고하고, 종료 시 요약한다.

```
🔁 ralph-loop · goal: "E2E를 5분 이하로"
  turn 1/15 … 측정: 612s  (미충족) → lessons append
  turn 2/15 … 측정: 470s  (미충족) → 직렬 fixture를 병렬화
  turn 3/15 … 측정: 268s  ✅ PASS (< 300s)
달성: 3턴 / 누적 교훈 3건 (.ralph/lessons.md) / verify: npm run e2e exit 0
```

## 5) 안전 규칙

- **종료 조건 3종 세트 없이는 출발 금지**(p18): 측정 가능한 상태 + 증명 방법(`verify`) + 턴 상한(`max-turns`). 셋 중 하나라도 없으면 먼저 물어본다.
- 서브 에이전트가 "끝났다"고 **주장**해도 믿지 말고 반드시 `verify`로 **증명**시킨다 (p18).
- 파괴적 작업(force push, 대량 삭제)은 루프 안에서 자동 실행하지 않는다. 커밋/푸시는 사용자가 요청할 때만.
- 무관한 파일까지 sweep 하지 않는다 — `goal` 스코프 안에서만.
