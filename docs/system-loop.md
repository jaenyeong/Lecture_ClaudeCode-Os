## 1) 핵심 루프 — 단계 분해 + 담당자

담당자: 🧑 사람 · 🤖 AI · ⚙️ CI/Hook

```
  ┌─────────────────────────────────────────────────────────┐
  │                                                         ↓
🧑 ① 요청      →  🤖🧑 ② 구체화   →  🤖 ③ 구현    →  🤖⚙️ ④ 검증
 (모호한 입력)     (/interview)       (스킬·코드·       (code-reviewer
                   객관식 Q&A)        서브에이전트)      fact-checker
                                                         ktlint hook)
                                                            │
  🤖 ⑦ 회고     ←  🤖🧑 ⑥ 출고     ←  ❓ ⑤ 기록     ←──────┘
  (/skill-stat)     (/commit·/push     (← 비어 있음)
                    계정 확인)
```

| 단계 | 담당 | 이 OS의 도구 |
|---|---|---|
| ① 요청 | 🧑 사람 | (자연어 입력) |
| ② 구체화 | 🤖 AI + 🧑 사람 | `/interview` (6축 신호등 → 객관식) |
| ③ 구현 | 🤖 AI | 스킬 작성 / 서브에이전트 / `ralph-loop` |
| ④ 검증 | 🤖 AI + ⚙️ CI | `code-reviewer`·`fact-checker`·ktlint/console.log hook |
| ⑤ 기록 | ❓ **없음** | — (세션이 끝나면 배운 게 휘발) |
| ⑥ 출고 | 🤖 AI + 🧑 사람 | `/commit`·`/push` (계정 정책 확인) |
| ⑦ 회고 | 🤖 AI | `/skill-stat` (호출 통계만) |

## 2) 병목·반복·낭비 1곳 → **⑤ 기록 단계의 부재**

**무엇이 문제인가**: ②~⑦ 모두 도구가 있는데, **"이번에 배운 것"을 OS 차원에 쌓는 단계만 비어 있다.** `skill-stat`은 *몇 번 썼나*(통계)만 알 뿐, *무엇을 배웠나*는 남기지 않는다.

**증거 (이 세션에서 실제로 반복된 낭비)**:
- `git`이 scm_breeze 래퍼에 깨져 커밋이 한 번 실패 → 재시도 (다음 세션도 또 겪을 것)
- `gh` 계정이 `jaenyeong-kim`이라 매번 스위칭 확인 (반복되는 마찰)

→ 이런 교훈이 **파일에 안 남으니 매 세션 0부터 다시 부딪힌다.** `ralph-loop`은 `lessons.md`로 *루프 안에서는* 이걸 해결했지만, **OS 전체에는 그 장치가 없다.**

**왜 1곳으로 골랐나**: 이 병목이 2·3번 과제의 입력이 된다 — ⑤에 "자산 축적형 자율 개선 장치"(2번)를 넣고, 그 효과를 "정량 지표"(3번)로 재면 루프가 *스스로 나아지는* 시스템 루프가 된다.

## 3) 자율 개선 장치 설계 (p55 PRACTICE 2번)

병목인 ⑤ 기록 단계에 **자산 축적형** 장치를 넣는다 (자율 탐지형 대신 — 단순·확실).

| 항목 | 결정 |
|---|---|
| **방식** | 자산 축적형 (겪은 교훈을 파일에 남김) |
| **언제(트리거)** | 세션 종료 시 자동 — **Stop hook** (`.claude/hooks/session_lessons.py`) |
| **무엇이** | "배운 것 / 반복된 마찰(같은 실수·우회)" 1~3줄 |
| **어디에** | `docs/lessons.md` (날짜별 append) |

**작동 원리**: 세션이 끝나려 하면 Stop hook이 Claude를 한 번 더 깨워(`decision=block`) "오늘 배운 걸 `lessons.md`에 남겨라"고 지시한다. `stop_hook_active`로 두 번째엔 통과해 무한 루프를 막는다. 다음 세션은 이 파일을 읽어 같은 마찰을 반복하지 않는다.

```
세션 종료 시도 → Stop hook 발동 → "lessons.md에 교훈 append?"
   → (배운 것 있으면) 기록 후 종료   → 다음 세션이 읽음 ↺
   → (없으면) 한 줄 보고 후 종료
```

> 확장 여지: 읽기 주입(다음 세션이 자동으로 `lessons.md`를 읽게)은 SessionStart hook으로 붙일 수 있다. 이번 스코프는 "쌓는 장치"까지.

## 4) 정량 지표 (p55 PRACTICE 3번)

2번 학습 장치(`lessons.md`)가 **실제로 효과 있는지**를 한 줄 수식으로 잰다.

```
반복마찰 회피율 = 1 − (재발한 마찰 수 / 전체 마찰 수)
```

- **무엇이 측정되나**: 한 세션(또는 주 단위)에서 생긴 "마찰" — 같은 실수·불필요한 우회·사용자의 반복 지적 — 중에서, **`lessons.md`에 이미 적혀 있었는데도 또 터진 것(재발)** 의 비율을 1에서 뺀 값.
- **재발 판정 기준**: 그 마찰에 해당하는 교훈이 `lessons.md`에 **이미 존재했는가**. 있었으면 재발(학습 실패), 처음이면 신규(어쩔 수 없음, 분모엔 들어가도 분자엔 안 들어감).
- **↑ 높음(1에 가까움)** = 학습 장치가 잘 작동. 과거 교훈을 안 반복 → 루프가 스스로 나아지는 중.
- **↓ 낮음(0에 가까움)** = `lessons.md`가 안 읽히거나 효과 없음. 같은 마찰을 매번 다시 겪음 → ⑤ 기록 단계 또는 읽기 주입을 손봐야 한다는 신호.

**예시 (이 세션)**: 마찰 5건(git 래퍼, gh 계정, 서브에이전트 verify, Edit-Read, hook 무한루프) 중 재발 0건 → 회피율 `1 − 0/5 = 1.0`. 단 이번 세션에 처음 기록한 것들이라, **다음 세션부터** 진짜 회피율이 의미를 갖는다.

> 확장 여지: Stop hook이 교훈을 남길 때 "이번에 재발한 마찰 수"도 함께 적게 하면, 주별 회피율을 자동 집계할 수 있다. (이번 스코프는 지표 *설계*까지)
